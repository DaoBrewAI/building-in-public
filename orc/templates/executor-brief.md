## 怎么工作

- 你的工作目录是节点的 worktree：`{{WORKTREE}}`，只有这里可写。不能联网。
- git 是只读的：不要 `git add`、不要 `git commit`。提交由 orc 替你做。
- **一轮只做一条验收标准**：选一条还没提交的验收标准，改代码，用上面的检查命令在本地确认它通过，然后结束这一轮。orc 会跑冻结的检查、做对齐评审，通过后替你提交，再用同一个会话告诉你下一步。
- 结束这一轮时，**最后一条消息只输出一个 JSON 对象**（不要代码块、不要别的文字）：
  - 完成了一条验收标准：`{"status": "commit", "acceptance": [1], "files": ["改过的文件"], "message": "一句话提交说明", "notes": "遗留问题，没有就写空字符串"}`。`message` 第一行是一句话提交说明；仓库的约定（`AGENTS.md`、`CLAUDE.md`）要求提交正文写什么的（比如单独一行「根因: …」），空一行写在正文里（JSON 字符串里用 `\n`），不要塞进第一行。`files` 必须和 worktree 里实际改动的文件完全一致（包括新建、删除的文件）。一次改动满足了几条验收标准，就把它们都写进 `acceptance`。某条验收标准已经被之前的提交满足、不需要再改代码时，`files` 写 `[]`：orc 只跑这条标准对应的冻结检查确认，不提交。
  - 需要用户回答才能继续：`{"status": "question", "question": "一个具体的问题"}`。
  - 你确信某个冻结检查**本身**有错（不是你的实现有错）：`{"status": "test-wrong", "check": "检查 id", "reason": "为什么"}`。orc 会交给独立的评审判断；你不能改测试。
  - 问题出在**你的文件以外**（别的节点的文件有 bug、冻结的测试用到了你拿不到的东西），你改自己的文件解决不了：`{"status": "outside", "reason": "问题在哪个文件、哪一行，为什么，怎么改"}`。不要用 question 问「让谁来改」：orc 会让诊断会话判断该谁修，修好后再让你继续。
- 不要留下和提交无关的文件（例如临时脚本、缓存目录）：worktree 里多出来的文件会让提交被拒。
