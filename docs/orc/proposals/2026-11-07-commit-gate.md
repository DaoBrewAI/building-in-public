# 提案：对齐评审放在提交关口里，不放进 broker 脚本

状态：**林翰 2026-11-07 选 A**。已改 PLAN「已确定的决定」的「提交」一行和阶段 4 的提交关口一条。

## 要解决的问题

「已确定的决定」的「提交」一行写的是：子任务一律通过 commit broker 提交；**broker 里**由 Claude 做对齐评审，偏离就拒绝，并发纠偏单。

读了复用的 `commit-broker.sh` 之后发现，照字面做有个问题：

- broker 处理每个提交请求时，全程拿着整个 mission 共用的生命周期锁（`process_request` 先拿锁，处理完才放）。STATE.md 的规则 2 要求 orc、broker、集成三者互斥。
- 对齐评审要调用一次模型，一次通常几十秒到几分钟；用 `review`（Fable）的深度评审更久。
- 评审放进 broker，模型思考的这段时间里整个 mission 都被锁住：别的节点提交不了，`orc step` 也跑不了。阶段 4 的重点是并行，这样就退回到实质上的串行。

## 方案

把「提交」拆成两段。评审照样在每次提交之前做，评审不通过就不提交，纠偏单照发。变的只是**评审在锁外面做**：

1. **提交关口**（orc，在锁外、后台运行）：
   1. 文件范围：只能改本节点声明的文件；动了冻结的验收测试，直接拒绝。
   2. 核对测试哈希：worktree 里的验收测试必须和签名时一致。
   3. 跑检查：这次声明完成的验收标准对应的检查，加上本节点此前已经通过的检查。不通过就直接拒绝，不调用模型。
   4. 对齐评审：调用 `northstar-review --role auto`，和提交前 hook 是同一个入口。DRIFT 就拒绝并发纠偏单；评审出错时不放行；diff 超过上限时拒绝，要求拆小。
2. **broker**（复用脚本，**一行不改**，在锁内）：做它原有的全部校验，然后提交。

**怎么保证提交的正是评审过的那份**：关口把评审过的改动算成 `diff_sha256`，写进提交请求。broker 本来就会核对：worktree 里现在的字节和 `diff_sha256` 对不上，就拒绝。所以评审之后哪怕改了一个字节，也提交不进去。

**额外的好处**：broker 和它的 40 项契约测试都不用动。
