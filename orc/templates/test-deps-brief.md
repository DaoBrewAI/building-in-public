你在检查一组验收测试有没有越过任务 DAG 的依赖。只读下面的材料，不要运行任何东西。

## 规则

DAG 里每个节点有前置节点（`depends_on`，层层往上都算）。节点 X 做完时，orc 只在「仓库原有的代码 + X 和它前置节点的改动」上跑挂在 X 上的检查。别的节点（和 X 并行的、在 X 之后的）新建的文件，那时**不一定存在**。

所以挂在 X 上的检查，跑到的测试只要在运行时需要别的节点新建的文件，这个检查就可能永远过不了。你要找的就是这种地方。

**要算**（运行时会去加载或读取那个文件）：
- `import` / `from … import …`（文件开头或函数里面）
- 把 `"模块:名字"`、模块名字符串交给会导入它的代码（例如 `make(tmp_path, "pkg.mod:attr")`、`resolve_processor("pkg.mod:attr")`、`importlib.import_module("pkg.mod")`）
- 在子进程里运行的代码字符串里导入
- 按路径打开、读取那个文件

**不算**：
- 只拿字符串去比较、断言，不会导入它（例如 `assert DEFAULT == "pkg.mod:attr"`）
- 用到仓库里原有的文件，或 X 自己、X 的前置节点新建的文件

## 输出

最后只输出一个 JSON 对象：

```json
{"findings": [{"check": "检查 id", "test": "测试文件路径", "line": "测试里那一行，原样照抄（去掉行首缩进也可以）", "file": "用到的、别的节点新建的文件路径（照抄 new_files 里的写法）", "why": "一句话：运行时为什么需要它"}]}
```

- `line` 必须是测试文件里真实存在的一行，并且这一行里写着那个文件的模块名或路径（例如 `pkg.intake.fake`、`pkg/intake/fake.py`）。只是用到前面导入的名字（例如 `fake.done(ctx)`）不要报，报导入它的那一行。
- 同一个测试的同一处，挂在同一个节点上的几个检查都跑到它，每个检查各报一条。
- 没有问题就输出 `{"findings": []}`。不确定的不要报。
