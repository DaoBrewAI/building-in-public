Data and durable state

Settled

Risk classification becomes mission state

Every mission records routine or material. Uncertainty is material. The active workflow gate is also recorded so a resumed coordinator cannot skip review or alignment.

Alternative rejected: infer risk only from chat history; it is not durable across sessions.

Settled

Next steps become a required artifact

NEXT-STEPS.md classifies follow-ups as ready, decision-needed, or deferred, and the board links it.

Alternative rejected: leave follow-ups only in the final chat response.

Workflow contracts

Settled

All missions use the same 10x spine

Plan → TDD → independent review → fresh verification → brokered commit → pre-merge status truth → merge → merged-tree verification → final status truth.

Settled

Material missions pause for alignment

User-visible, security, privacy, data, contract, production, infrastructure, cost, release, or long-running changes require a walkthrough report, quiz pass, and explicit merge approval.

Routine missions still generate truth reports but may merge automatically.

Settled

Status truth stays conservative

Automated tests can prove tests-green, never witnessed-live. Green requires a matching running/build SHA and captured evidence.

User-facing behavior

  1. The task board shows risk and the exact active gate.
  2. Every mission links durable pre-merge and final status HTML.
  3. Material missions visibly enter awaiting-alignment and immediately notify the user instead of silently waiting.
  4. Final handoff always includes implementation evidence, status truth, and classified next steps.
