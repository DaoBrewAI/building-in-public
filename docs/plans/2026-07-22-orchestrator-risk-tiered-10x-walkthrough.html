Orchestrator now proves each gate instead of merely naming it.

This change turns the preferred 10x workflow into durable mission state, deterministic shell gates, and HTML evidence. It intentionally pauses material work before merge so you can verify both what changed and what has actually been observed.

1. Context

P0 modularization completed, but the expected follow-through—review, truthful status, merge discipline, and HTML reporting—was not consistently visible. The root issue was that the skill described parts of the workflow without making every transition fail closed when evidence was missing.

2. Intuition

Think of each mission as moving through two airlocks. The worker airlock proves the code-making process; the coordinator airlock proves it is safe and understood before merge and archive.

Designbrainstorm + written plan + plan review HTML
Worker airlockTDD + independent review + fresh verification
Coordinator airlockfeature SHA + status truth + risk alignment
Acceptancemerge verification + final truth + classified next steps
The governing rule: tests can prove tests-green; only a matching running/build SHA plus captured observation can prove witnessed-live.

3. What was done

Worker evidence

Pipeline gate

pipeline-gate.sh now rejects missing or fragmentary plan review HTML and missing TDD, review, verification, deviation, or follow-up evidence. The brief and report templates tell the worker exactly which 10x skill owns each stage.

Coordinator evidence

Risk alignment gate

The new alignment-gate.sh requires brokered commit evidence and pre-merge truth for every mission. Material missions additionally need standalone walkthrough HTML, a recorded quiz pass, and explicit merge approval.

Durable state

Mission and board

MISSION.md persists risk and the active workflow gate. The board adds awaiting-alignment and links plan review, walkthrough, pre-merge truth, final truth, acceptance, and next steps.

Authority boundary

Next steps

NEXT-STEPS.md is coordinator-owned after the worker stops. Every follow-up must be ready, decision-needed, or deferred; suggestions never silently become implementation authority.

4. Deviations & judgment calls

  1. A deterministic coordinator script was added rather than relying on prose in the skill. This makes pre-merge and final/archive failures reproducible.
  2. Plan review HTML became a worker-side required artifact. Markdown alone did not satisfy your requirement to always receive HTML reports.
  3. NEXT-STEPS.md was moved out of worker provisioning after review identified that it carries coordinator authority.
  4. No review subagent was spawned because the active system constraint forbids delegation unless you explicitly request it. I performed a separate full-diff review locally and resolved two Important findings before commit.
  5. The publication plan changed from immediate ready PR/merge to draft PR plus this quiz and explicit approval, because the governance change classifies itself as material.
